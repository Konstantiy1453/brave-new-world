**二、确定的缺陷及修复验收建议**

P1 表示应在下一轮对外试玩之前优先修；P2 表示明确问题，应随基础修复收敛。以下“建议”均未实施。

**F01 / P1：自动出口抢先消耗跨区建设物资。**

- 实测：正常推荐经营路线中，河谷第一座农场建成后，建材在第 29 日至第 400 日的各记录检查点均为 0；首府后期在第 180 日至第 400 日的记录检查点保持 90 建材。以完全相同的第 400 日状态对照，第 401 日港口正常运行会卖掉新产的 2.4 建材，不发建材陆运；暂停首府货运站后反而能发出 2.4 建材和 0.8 部件。
- 原因：日结先贸易、后陆运；出口与调拨都使用同一保留线。出口先吃完调拨需要的盈余；建材进口只补至 35，也达不到 90 的调拨保留线。
- 后果：玩家看似有加工、有道路，前哨仍扩建不了，必须关闭整座贸易设施绕过规则。
- 建议：把本地保底、已承诺的建设/调拨、可出口余量分开计算；国内调拨先预留，再出售真正盈余。提供目标库存及明确调拨入口。
- 验收：起点正常加工且港口开启、目的地缺建材时，可以持续供给扩建；不能用单纯停卖全部商品掩盖问题。
- 位置：[sim.gd:186](../game/simulation/sim.gd#L186)、319、336、451。证据：[economy_replay_audit.json](../evidence/runtime_fix_20261029/economy_replay_audit.json) 的 `logistics_probes`。

**F02 / P1：民营企业允许在必亏地区成立，停业后没有恢复途径。**

- 实测正常动作：首府双矿，15 日远征连路，20 日在 18 人前哨批准服务社。每日潜在收入上限 6.3，工资 9、固定成本 5；连续亏损 15 天后，第 38 日停业。当时仍为合同考核中，公共资金 6076.95、企业资金 352.5。再申请企业返回“本 Demo 已有一家民营企业”。
- 后果：不能复业、迁址或清算重建，但合同要求一家营业中的企业。这个状态失去达标途径。该回放最终在第 42 日因粮荒失败，不能把最终失败原因写成企业停业；死局在此前已经独立记录。
- 建议：审批前展示当地需求、预计营业额和最低成本；企业规模随需求调整；至少提供一种有代价的重组、迁址、复业或清算后重建。
- 验收：允许玩家犯经营错误并付出代价，但正常动作不能无提示地永久封死合同条件。
- 位置：[pages.gd:232](../game/ui/pages.gd#L232)，[sim.gd:152](../game/simulation/sim.gd#L152)、366、381、405、418。证据：同上 `scenarios[1].first_closure`、`reopen_while_active`。

**F03 / P1：部分整数及文本种子导致全球显示和实际经营地理不一致。**

- 实测 130 个固定采样点：260129 与 222415543 均 0 处海陆失配；2147483648 和 4294967297 均 40 处失配，矿区—河谷的普通陆路不可达。该探针没有验证这两个异常种子的跨山路线，不能据此认定所有生存路径失败。
- 原因：噪声种子被截成有符号 32 位，另一些地理参数和全球图集继续使用原值，形成两个世界。
- 文本探针确认 `Hello World`、`abc123`、`殖民契约` 的哈希也进入溢出入口；未对这些文本分别完成世界生成，不能套用上面的 40/130 统计。
- 建议：输入统一规范化一次，所有生成、采样、地区和图集读取同一有效种子；有符号 32 位范围内（−2147483648 至 2147483647）的种子保持原世界结果。受影响旧档要保留旧地理或明确迁移，不能读档时静默重造地形。
- 验收：正负边界、大整数、文本输入，以及同档球面/平铺/局部/路网一致性。可玩性失败要在进入游戏之前给出处理，不能让合同要求不可达系统。
- 位置：[main.gd:378](../game/ui/main.gd#L378)、[world_gen.gd:12](../game/world/world_gen.gd#L12)、[seed_geography.gd:58](../game/world/seed_geography.gd#L58)、[map_view.gd:364](../game/world/map_view.gd#L364)。证据：[world_seed_range_audit.json](../evidence/runtime_fix_20261029/world_seed_range_audit.json)、[text_seed_hash_audit.json](../evidence/runtime_fix_20261029/text_seed_hash_audit.json)。

**F04 / P1：地区按钮重复点击也会重新计算整片地形。**

- 同步函数实测首次约 5.38 秒，同地区重复约 4.60 秒，离开后返回约 4.54 秒，另一地区首次约 5.06 秒。
- 原因：每次进入都清场并重建。地形只有 7569 个唯一网格点，却展开 44376 个顶点，颜色与高度重复调用约 88752 次地理采样；海面另有 10716 次采样。
- 建议：先复用唯一格点的高度/颜色，再缓存最近地区；保持现有分辨率与三角形规则。缓存标识独立于当前选区，换世界失效，建筑变化时只更新必要内容。进一步耗时再拆分为可取消的后台计算或分帧工作，并显示忙碌状态。
- 验收：同地区重复进入不重建地形；离开期间新建/停工的建筑返回后仍正确显示。测量真实窗口点击到反馈、点击到稳定显示两项耗时，不仅报平均 FPS。仅把大计算放进延迟回调并不会消除阻塞。
- 位置：[map_view.gd:136](../game/world/map_view.gd#L136)、776、883、984。证据：[perf_before.json](../evidence/runtime_fix_20261029/perf_before.json)。

**F05 / P2：管理面板打开时，空格路径可以恢复模拟。**

- 隔离集成实测：第 29 日打开财政面板，向 `_unhandled_input` 发送空格，再推进 5 秒；面板仍开着，`paused=false`，日期变为 30。
- 这是未被控件消费的键盘路径，不表示每个按钮获得焦点时都必然触发。与 README“打开管理面板会暂停”的承诺不一致。
- 建议：先确定面板策略并统一时间入口。若面板强制暂停，快捷键和加速键也应遵循；若允许边看边运行，必须显示明确状态并避免点击错位。
- 验收：打开不同管理页、不同焦点、空格/速度按钮/关闭面板后，行为一致。
- 位置：[main.gd:171](../game/ui/main.gd#L171)、194–208。证据：[ui_behavior.json](../evidence/audit_20261030/sandbox/ui_behavior.json)。

**F06 / P2：成功时虽然设了暂停，同一帧的追赶循环仍继续结算。**

- 第 37 日、12×速度，注入 5 秒帧间隔：第 38 日达标应停止，实际结算到第 49 日，最后 `paused=true`。
- 这是集成边界复测，不是宣称每次正常成功都会跳 11 天。地区加载阻塞与高倍速使这一组合有实际意义。
- 建议：出现成功、失败、强制暂停或其他中断后立即退出结算循环，并明确处理剩余累积时间。场景计算时间是否计入模拟也要统一。
- 验收：低帧率/长帧下成功及失败准确停日；继续后不悄悄补算积压日期；普通 1×/4×/12×保持同模拟时长规则一致。
- 位置：[main.gd:174](../game/ui/main.gd#L174)。证据：同上 `success_pause`。

**F07 / P2：住区停工后保留全部住房，却免去运营负担。**

- 实测竣工住房 125、电力需求 12、水需求 4.2；停工后住房仍 125，电力降 11、水降 3.2。源码同时确认停工建筑跳过维护费计提；本探针没有单独记录该建筑的维护流水。
- 建议：明确停工语义。停用应退出可用住房；若只是关闭服务但仍可居住，则保留基本维护并降低居住服务水平。具体采用哪一种需要设计决定。
- 验收：停用、启用、读档均没有免费保留全部功能的状态。
- 位置：[sim.gd:230](../game/simulation/sim.gd#L230)、262、558。证据：[economy_boundary_audit.json](../evidence/runtime_fix_20261029/economy_boundary_audit.json)。

**F08 / P2：没有货运站的据点也报告港口吞吐已满。**

- 实测河谷只有电站、水站和农场，食品充足，在多个经营及长期检查点持续出现这条警告；代码对零容量会固定触发该警告。
- 原因：剩余容量为零就报警，把“没有港口”和“实际拥堵”混为一谈。
- 建议：只有存在港口且有被容量限制的真实贸易需求时提示拥堵；无设施、无需求分别处理。
- 位置：[sim.gd:348](../game/simulation/sim.gd#L348)。证据：经济回放及长期结果。

**F09 / P2：新建游戏后地图选区可能残留。**

- 先选择地区 5 再新建游戏，主界面选择变为 0，地图内部选择仍为 5。读档路径本次检查一致。
- 建议：新局统一重置并同步选择状态，避免右侧操作对象与高亮不同。
- 位置：[main.gd:381](../game/ui/main.gd#L381)、[map_view.gd:61](../game/world/map_view.gd#L61)。证据：[map_state_audit.json](../evidence/runtime_fix_20261029/map_state_audit.json)。

**F10 / P2：干旱描述和实际数值不一致。**

- 文案写供水可能降至 55%；限水选择实际为供水能力 ×0.8，矿场/农场/加工产出另 ×0.85。
- 建议：先统一设计数值，再由同一效果数据生成选项说明；界面同时显示直接成本与持续影响。
- 位置：[economy.json:33](../game/data/economy.json#L33)、[sim.gd:267](../game/simulation/sim.gd#L267)、553。

**F11 / P2：同一干旱选择，主动回应与超时实际作用天数不同。**

- 10 月 30 日对照实测：主动选限水影响第 40–51 日，共 12 次生产；超时默认限水第 40 日生产先结算，只影响第 41–51 日，共 11 次。
- 例：被观测矿产每日增量从 8.7979 降为 7.4782；主动分支在第 40 日开始降，超时分支第 41 日才降；两者均在第 52 日恢复。
- 建议：明确日初、生产、日末决定的统一顺序，以及“持续 N 天”的含义；选择时刻不同可以影响后果，但要成为可见规则。
- 位置：[sim.gd:172](../game/simulation/sim.gd#L172)、501、517。证据：[event_timing.json](../evidence/audit_20261030/sandbox/event_timing.json)。

**F12 / P2，静态潜在问题：道路显示与模拟对停运截止日差一天。**

- 显示判断 `blocked_until > day`，运输判断 `blocked_until >= day`；截止日地图显示正常，实际仍停运。
- 当前三个标准事件没有形成完整的道路事故链，此项是未来扩事件前需统一的潜在缺陷，未作为当前正常事件流程中的运行复现。
- 建议：道路、事件、合同连通性共用同一截止日规则。
- 位置：[map_view.gd:1037](../game/world/map_view.gd#L1037)、1149；[sim.gd:425](../game/simulation/sim.gd#L425)、444。

**三、流畅度与 UI 判断**

10 月 29 日探针是一次同步处理耗时采样，不含操作系统输入和最终渲染，不是多轮 P95。可以确定存在工作量，不能据此宣布用户当时全部卡顿都来自同一原因。

| 操作 | 已测同步耗时 |
|---|---:|
| 启动 / 读中期档 | 1990 / 720 ms |
| 星球档案 / 建设目录 | 480 / 469 ms |
| 财政 / 科研 | 289 / 290 ms |
| 交通 / 民营 / 合同 / 事件 | 238 / 189 / 251 / 272 ms |
| 保存设置页 | 138 ms |
| 地区首次 / 同地区重复 / 返回 | 5383 / 4598 / 4540 ms |
| 球面 / 平铺切换 | 12 / 14 ms |
| 一次模拟日＋地图与界面同步 | 14 ms |

用户反馈财政/殖民预览目前已缓解，应保留这一实际感受；本轮没有抓到当时内存状态，不能诊断为内存问题，也不能说卡顿已被修复。有限同步检查中地图节点保持 174、材质缓存由 33 增到 85 后稳定、孤儿节点 0，没有发现该路径持续泄漏。

优化次序建议：地区重复重建 → 管理页整页重建/字体与控件创建计时 → 地图预览与精细贴图的主线程阶段 → 状态刷新时不必要的标记重建。后两项目前是代码发现的风险，尚无单独计时归因。保留清晰地形和字体，不先靠降低观感换速度。

下一版可以采用待验证的体验目标：普通按钮在约 100 ms 内给出可见反馈；重复打开已加载地区接近即时；耗时生成显示进度并能取消，主界面仍响应。目标值是设计建议，不是本轮达成结果。

信息组织比换皮更紧迫。财政页应首先回答“最近赚多少、主要支出、未来已承诺支出、现金还能撑多久”；地区页应首先回答“缺什么、为什么缺、能在哪里解决”。自动贸易与运输应明确显示各自保留量、预定用途、出发/抵达日期，不能只展示全局总量。红色警报必须对应真实、可操作的问题，否则 F08 一类误报会破坏玩家判断。

基地目前为自动槽位布局的低多边形沙盘。实际画面能区分部分设施，但比例、地形衔接、材质、道路接口与运转状态表达较弱。玩家尚未通过建筑摆放作出空间决策，不应把近景表现误称为已经具备城市建造深度。按用户顺序，精修模型放最后；现在先约定建筑占地、入口、状态、区域地块与交互规则，之后资产才能稳定复用。

**四、玩法、节奏与平衡**

**B01：初次合同太早结束，系统尚未形成相互依赖。** 三种自动路线分别在第 38、36、38 日成功，合同期限 240 日。按一天 5 秒，36–38 天只有约 3 分钟基础模拟推进；这不含阅读和操作，也不能代替真实新玩家时长。目标 20–40 分钟仍未通过计时试玩。建议把合同分成生存启动、双据点分工、独立经营三个里程碑，使每阶段有一项要解决的新矛盾；不要仅延长科研和施工等待。

**B02：开局优势的长期差别仍需等价投入对照，科研回报需要单独调平。** 三条路径都可行是优点。设计上应让资本路线更抗现金波动、工人路线更快形成产能、科研路线更早获得降本/勘探/风险信息。当前同一资本开局的固定策略对照中，不科研路线第 400 日现金 38507.11；第 60 日建研究所并研究勘探路线 37513.87，少 993.24。这只是两条策略的科研回报信号，不证明所有技术无用，也不能作为三种开局的长期比较结果。下一轮要比较等价投入下的不同优势，而非只证明都能通关。

**B03：高收益资源和科研没有足够明显的阶段推进。** 三矿开局可采符合原需求，不需要生硬锁成“先碳后金属”。应通过矿床深度/品位、装备、供水、运输、加工和市场要求，让初始可采与规模开采不同；技术可开放新方法和降本选择，而不仅加百分比。

**B04：地理确实影响经营，但路线取舍需要重新校准。** 推荐种子普通路 1124 km、9 日、1570；跨山 635 km、3 日、1638，运力还由 28 提至 42。仅多约 4.3% 初建资金，时间缩至三分之一并增加运力，长期吸引力明显偏向跨山。这是推荐种子的比较，不是所有世界均如此。可以用更高初建/维护、工程时间、技术要求、风险或季节条件形成两条合理路线，避免选项只是显而易见的优劣题。

**B05：世界随机性已存在，经营候选角色仍较固定。** 种子会改变地貌与路径，但六个候选保留功能角色；再多地形纹理也不自动产生更多经营流派。建议在保证至少一条生存路线的前提下，变化资源组合、水源稳定性、耕地、道路瓶颈和移民吸引力，使“先农业、先加工、靠进口换速度”都可能合理。先修 F03，再拓宽种子分布。

**B06：产业转型与履约后目标不足。** 矿床确实会耗尽，长跑时公共经营转亏，但当前只有一种本地服务社，服务主要来自殖民地居民消费，无法自然替代对外矿业收入。应设计实际外部需求或减少外部支出的转型，例如加工品订单、农产品外销、科研委托、维修/补给服务；各自有条件与履约成本。下一版只选一条形成完整替代现金流，不同时铺开完整市场经济。

**B07：产能过剩没有合理处理。** 成功档继续至第 6200 日，河谷 35 人囤食品约 71683 吨，可吃 12800.55 天；当前没有相应仓储、损耗、食品出口或按目标停产。建议先选仓储上限＋目标库存生产，或食品销售等一种闭环。无限堆积让经营判断逐渐失去意义。

**B08：自然增长的时间尺度与短局不同。** 出生每 360 日一次，初始儿童第 2880 日成年，新生儿需 5760 日成年。长跑验证这些转换在发生；这不是计算错误，而且原 Demo 允许以移民为主。但若未来要呈现人口世代，就要明确“模拟日、年度、阶段跨度”，否则几千万到几亿人口只会是标签。当前优先做好移民、培训、住房、就业四者的关系，不增加逐人模拟。

**B09：混合经济已经有真实账户，但尚未承担后期管理转型。** 服务社有外来投资、雇工、工资、消费、税，值得保留。后续需要让企业根据需求申请扩张、选择可经营区域、承担部分公共服务或产业；玩家管理许可、税、最低供应、投资预算和异常。自动化既要节省操作，也要解释为何生产、为何停工、为何不扩张。单纯再增加十种设施会增加点击负担。

**B10：困难应来自可预测的代价与不确定性管理。** F01/F02 造成的无解不能算难度。可玩的难点是资金、物流、生态、劳力、科研之间的竞争，而且玩家在坏局面里仍有收缩、改线、重组、放弃部分收益的空间。失败条件应保留，但应能追溯到自己的决策或已揭示的风险。

建议采用“短事件池＋少量手工分支链”。先做 8–12 个短事件和 3 条完整链作为下一轮可玩验收范围，之后扩到专项草案的 6–8 条链。这里是讨论建议，不是已经批准的新开发范围。数量不是主要验收标准：同一链的不同选择应产生不同局势，一局不必把所有内容看完。

短事件可覆盖纯机会、可控事故、经营两难、科研发现与社会变化。保留一些纯好运和中性发现；不把每个礼物藏成陷阱。负面事件之间留恢复空间，重大事件同时激活数量受限。依据当前土地、产业、人口和历史筛选后再抽签，不能无港口遇港口拥堵、无人口接到大型商会争端。

例如“第二条水位线”不应是花钱直接买一个好结局。先调查可能花费科研能力并延误扩产，却获得地质信息；抢修能立即扩产，但在特定地质条件下进入盐渍化支线；坏结果还可以追加排盐投资修复。多项选择都应有成立条件，避免永久存在唯一正确答案。

为突出陌生星球的探索感，可在生态、地质、异常观测中加入待解现象，逐步揭示与产业的关系。下一轮不宜把每条链都做成财务罚单，也不必马上加入银河战争或大规模外星剧情。

事件框架最低需要：

1. **定义与实例分开。** 定义保存条件、节点、选择、效果和后继；实例保存绑定地区/企业/货单、已作选择、节点、变量与结局。
2. **调度有依据。** 支持里程碑、条件、延迟日期及工程/运输完成触发，使用独立且随存档保存的随机流。
3. **后果走真实系统。** 钱有付款方，货有来源，移民有目的地；道路封闭、矿床勘探、供水工程实际改变模拟，地图显示对应状态。
4. **一次性结算。** 同一结局被重复调用不能重复送钱；目标失效、企业停业、超时或取消有明确处理。
5. **可查历史。** 玩家能看答复期限、确定成本、可知风险、调查收益、进行中链条及长期修正。
6. **可测试内容。** 新事件 ID、目标和效果必须验证；当前未知事件可能被清空并返回“成功”的处理方式要改为明确报错。每条链测所有结局、超时、读档继续及重复结案。

先落地这套最小框架和三条有真实经营后果的链，再写几十条文案。否则扩充越快，越难检查效果和旧档兼容。

## 2. 产品方向与本次范围

玩家是殖民公司的外派经营者，携带有限人员、资金和装备登陆宜居星球，签署对赌协议。通过矿业起步，逐渐发展农业、加工与公共服务，引入能够自主运营的民营企业，形成可持续殖民地。达标后取得总督资格，可继续经营，也可交给代管并前往下一颗星球。

当前版本的完整循环：

    选开局与星球 → 登陆及经营 → 科研与产业取舍
        → 事件与公司关系 → 达标获得总督资格
        → 选择代管 → 新星球开局 → 老星球按游戏时间分红

必须保留初始“资本支持、科研人才、生产劳力”等不同优势，并比较其真实收益。初期有多种可开采矿产，不能倒退成只允许先采一种低级资源。

当前交付范围：

- 修复审查报告 F01—F12 对应的行为问题，并复核性能。
- 一个宜居世界生成体系、有限数量据点，以及可玩的跨区分工；新星球至少能使用另一种子生成不同局势。
- 有限人员驱动的科研分配。
- 最小但真实的经济、社会、环境因果反馈与公司介入。
- 有条件随机事件池和原创分支链。
- 至少一种可验证的后矿业经营路径，例如有外部付款方的加工订单；保留有限矿床。
- 总督任命、B 代管、下一星球与跨局存读。
- 简单、标准、困难使用同一机制；先校准标准，再生成压力不同的配置。
- 支持以上机制的中文 UI、批量操作与信息解释。

本次不展开：A 多星球同时亲管、银河外交战争、舰船贸易模拟、全部星球类型、完整地球物理气候、逐人日程关系、完整自由市场、多代人口巨量模拟、DLC 商业系统、大规模重新制作美术资产。

海洋、高山、极地、荒芜等星球是后续情景方向。它们代表不同挑战，不能仅凭类型名称强行决定难度；当前没有海运就不能把必须跨海的世界当作正常可玩开局。新增星球只在已经支持的生成与运输能力范围内变化。

本轮首先验证完整可玩片段。原 Demo 的 20—40 分钟可作为首次任职的候选体验目标，必须实测；此前讨论的 2—3、4—5、6—8 小时是未来体验设想，不是本轮必须通过等待凑出的时长。

过剩生产要有闭环：本轮优先做目标库存驱动的自动减产/停产，以及清楚的仓储或销售规则，避免无限囤积食品。不得直接删除库存来假装解决过剩。

贸易与生产操作需要批量管理：至少能按据点或类别批量启停、设置库存/贸易目标；已经存在升级机制的设施提供批量升级预览，显示资金、材料、劳力、水电影响。若尚无等级系统，不为凑“批量升级”而扩建无关科技树。

升级方向以效率、能力和选择增加为主；扩张仍有总投入和运维成本。保留民营企业自主运营、玩家管许可/税率/供应策略的方向。

## 4. 科研：有限人员分配与递减收益

已确认的含义是研究速度：

- 在人员能力、设备、经费等条件相同的测试中，10 人速度为 1，5 人速度为 0.6。
- 若某同等工作量项目由 10 人需要 4 个月，5 人约需 6.67 个月。
- 10 人先后做两个项目，约第 4 个月取得第一项、第 8 个月全部完成；5+5 并行约第 6.67 个月同时完成。这里的 4 个月是算术示例，不是所有技术的工期。
- 分散研究有总吞吐收益，集中研究能更早取得一项急需技术。这项取舍必须在实际玩法中成立。

实施要求：

1. 人员为真实有限资源。科研人员来自现有人口、移民或培训，不能同时在多个项目、科研岗位和其他全职岗位重复计入。
2. 人数增加不应使同一项目变慢，但边际贡献递减。可使用满足比例的幂函数作为初稿：R(n)=R10×(n/10)^α，α=ln(0.6)/ln(0.5)，n=0 时 R=0；也可采用满足同样校准关系的其他可解释曲线。
3. 上式仅是候选函数。10 是校准参照，不是永久科研总人口上限；研究量、设施能力、经费和团队规模都配置化。
4. 防止把全部项目拆成极小团队就总是最优：用真实实验设施能力、项目最低团队要求和项目成本约束。项目最低团队不能破坏 5 人正常开展校准项目的要求。
5. 不机械设置永久固定的“全游戏只能研究 2—3 项”。初期自然只能支撑少数团队，后续扩建与人口增长可增加能力；任何并行限制都要有设施或人员来源。
6. 调配、暂停与恢复保留已完成研究量。先采用零切换损失的简单规则；若引入准备成本，必须有实际玩法理由与 UI 预览。
7. 人员减少、设施停用、资金不足时，按明确优先级调整投入，显示原因。不得出现负分配、超员或空项目继续满速推进。
8. 科研与事件调查共享实际可用研究人员；派人考古后要反映到项目速度。
9. 技术至少包含能力解锁和经营改善，例如更深矿床开采、作物适配、加工/节水效率、风险识别及事件选项；不要全部只是微小百分比。

科研 UI 显示：总人员、已分配/可用人员、各项目投入、相对速度、剩余工作量、预计完成日期、缺少的设备/经费，以及调配前后的变化。所有进度按游戏时间推进。

## 5. 公司不信任、整改和有条件介入

以 0—100 的“公司不信任度”作为可见总表。具体增长率、阶段阈值和宽限时间由模型与测试确定。用户曾举过每月 +10、+5、+20、持续 3—5 个月等例子，这些不能直接当成定稿。

此前“九条红线同时满足四五条就输”的方案已被替代。保留经济、社会、环境三条因果链作为问题来源，并把核心违约与普通预警分开。

同时审查当前 _contract()、_fail() 和相关日结路径：现有欠款、饥荒、合同到期的直接判负必须与新审查流程统一。不能只在界面新增不信任条，却让旧失败入口在整改或援助期间提前结束游戏。确需独立终止的不可逆状态应明确列出、提前提示并测试，不能从旧实现里无意继承。

本轮的最小因果实现应真实可追踪：

- 经济：还款或必要支出逾期 → 经营履约风险；单纯投资期亏损与有计划融资不等于立即违约。
- 社会：持续缺乏工作/住房/必要服务 → 人口向星球外流失 → 生产或税基下降。星球内部迁居不算人口逃离。
- 环境：地区污染/资源透支 → 当地健康或生产条件恶化 → 医疗或治理支出、岗位效率变化。只实现足以产生决策的汇总反馈，不增加逐人疾病模拟。

严重程度与持续时间共同影响公司评价。同一违约导致的多个症状不能机械全额重复处罚。UI 展示当前值、本期变化、主要原因、持续时间、下一阶段条件和可行整改动作。

建议状态过程：

    正常经营 → 关注/预警 → 正式审查与整改
        → 有条件援助或接管准备 → 恢复正常 / 最终收回授权

状态不只看分数，还需要记录审查函、整改目标、期限、已接受条款及执行情况。公司决定有明确原因；最终判负前必须有玩家能够响应的过程，不能同一帧跳过全部阶段。

**有条件介入是本轮核心玩法，必须实际实现。**

- 公司能提供针对问题的物资、设备、周转资金或技术援助。
- 代价可以是暂时提高公司分成、指定整改工程、优先履行一份供货义务、限制非必要扩张等。
- 首版选择少数真正可执行的援助类型，完整贯通申请、条款预览、接受、到账或到货、义务追踪、履行完成。
- 接受之前明确援助内容、交付时点、未来成本、限制、结束条件与不履约后果。外部物资按交付机制进入库存，不能只改文字。
- 援助条款不能同时禁止玩家完成整改所必需的建设、融资或生产。
- 不因不信任升高就无差别降低所有产出、提高所有成本。真实缺水、停电、污染仍有对应地区的实际后果。
- 公司救助有边界，不能重复领取同一援助或无限刷新宽限期。
- 原公司税费、救助追加分成和后续代管分成各有清楚口径，不能重复扣同一项费用。

恢复规则：

- 违约解决后停止新增该项处罚；可核实的改善应能阻止继续升级。
- 持续稳定逐渐恢复信任，不要求一帧内把全部指标变绿。
- 阈值附近抖动不能清空持续违约历史；反复接受整改也不能自动重置期限。
- 捐赠、出售遗物等无关收入不能直接洗掉仍在持续的严重违约。
- 紧急局面至少有短期应对，例如进口、限产、调拨、收缩或援助。科研用于中长期改善，不能成为唯一救命按钮而又来不及完成。

最终接管或履约失败时，结算报告指出原因、演变过程、公司已提供的窗口和玩家选择。保留普通存读档，不强制铁人模式。

## 6. 事件系统与内容

采用“有条件的短事件池 + 手工编写的分支链”。当前三个固定日期弹窗不足以承载目标体验。

先完成审查报告建议的最小内容规模：8—12 个短事件、至少 3 条有完整结局的事件链。数量是此次迭代的内容目标，质量以真实选择、因果后果和存读可续为准。公司审查/救助通知不替代这三条独立内容链。

建议三条主链：

1. 水源/农业链：调查、扩建或节制利用的选择，产生供水、土地或治理成本的后果。
2. 工业/运输链：接订单、安排加工或运输、处理意外与交付，形成可核对的收益及风险。
3. 小型考古链：早期营地、废弃设施、地层遗迹等，能在本地完成调查，也可出售后续调查权。

优先参考 events_review.md 中的原创候选，按当前已实现系统改写。不要求把八条候选一次做完。

事件框架必须具备：

- 条件筛选后按权重抽取；条件包括地区、设施、人口、产业、合同阶段及此前选择。
- 正面机会、负面事故、经营两难和中性发现都有内容；保留真正的好运。
- 负面大事件有冷却和并发上限，给玩家恢复空间；具体频率和比例实测。
- 实例保存唯一 ID、定义版本、当前节点、绑定对象、历史选择、变量、计划后继和结局。
- 后续可由日期、工程完成、交货、调查进度等触发。检查事情是否实际完成，不能只检查按钮按没按。
- 效果影响真实资金、物资、就业、路线、供给、设施能力或持久修正；通过统一规则执行，留来源记录。
- 未知定义、失效目标、企业停业、道路替换、退出调查、重复结案有明确处理。
- 事件随机流与世界生成/渲染分离，保存状态；打开菜单或切换地图不改变抽签。读档相同行为可重现后续。
- 展示确定成本、可知收益、持续影响及已知风险。调查可增加信息、改变后续选项或风险，不把一切写成无提示掷骰子。
- 必须由玩家决定的节点自动暂停。若允许“稍后处理”，只能由玩家明确选择后继续运行，并显示游戏时间期限；暂停时期限不流逝。
- 统一自动到期和主动选择的效果生效规则。事件历史可查询结局及仍生效的影响。

考古范围：

- 小故事保留完整结局，例如取回失联勘探队记录、查明废弃设施原因、保护一处遗迹或取得研究样本。

## 7. 总督任命、生涯与 B 代管

取得总督资格是当前星球主要合同的完成。玩家可以继续经营，也可以交接后开始下一颗星球。不得把“必须达到完美成熟经济”新增为任命条件；实际移交状态影响分红和预测。

未来的 A：同时亲自管理新旧星球，获得旧星全部可分配收益并处理全部事项。本轮不实现 A，不给玩家可点击但无效的选项。

本轮的 B：旧星球交给代管，玩家获得部分可分配净收益，日常事项自动处理。用户举的 2/3 是未经检验的示例。请配置分成比例，说明初稿依据并测试。

**分红口径**

    当期经营收入
      − 当地生产、维护、工资与公共服务支出
      − 原有公司税费及仍有效的援助合同义务
      − 必要的当地周转/维护留存
      = 可分配净收益

    玩家分红 = 正的可分配净收益 × 玩家代管分成比例

明确代管方分成与代管费用的关系，不重复收费。账本能对上当地留存、公司所得、代管所得与玩家所得。没有可分配盈余时可减少或暂停分红，不能凭空保底发钱。

玩家转往新星球后，已任命星球的主合同不重新判负；仍未履行完的救助义务保留在当地结算中。当前活动星球若最终被收回授权，本次经营挑战结束，提供失败报告与读档/重开入口。过去已取得的总督资格和代管资产记录不因本次失败自动被没收；首版采用下述完整检查点恢复，不额外引入永久惩罚制度。

**移交与后台模型**

- 保留旧星球完整交接存档和世界身份，为后续扩展留基础。
- 首版运行汇总经营模型，无需后台执行旧星球完整逐日物流、建筑与事件模拟。
- 以一段代表性经营记录和实际生产能力形成基准，区分经常收入、库存变卖、援助、借款与一次性奖励。
- 已知负债、公司条款、有限矿产及正在发生的经营趋势进入预测。临时关闭维护或卖空库存不能换来永久高分红。
- 矿业收入不能在资源耗尽后原额永久持续。可按简化储量和生产能力推进，也可采用明确的可持续产能折算；方法与限制写入报告。
- 日常故障、普通供需波动与维护由代管方处理，首版只需结算简报，不强迫玩家返回旧星球。
- 可减少/暂停分红，但不能自动从新星球扣款，也不能产生隐藏的无限补贴义务。额外援助是玩家主动选择。
- 事件、历史和财务数据采用有界记录或汇总，不能每个月无限复制全部旧世界。

**生涯时钟与转账**

- 所有星球共享同一游戏时间。当前星球推进一个月，旧星球对应结算一个月；暂停时均停止。
- 不使用现实时间离线产钱，不因切换星球、加载菜单或重新打开存档重复结算。
- 同时保存生涯日期和每颗星球的登陆日期，换星球不能重置旧星球的结算账期。
- 新星合同期限、开局保护和按殖民年龄触发的事件从该星登陆时起算，或建立时转换成明确的全球截止日期。不能把第一星球的绝对日期条件照搬到第二星球。
- 分红必须是一次可核对转账：旧星可分配资金减少，玩家侧资金增加。同一笔钱不能留在两个账户。
- 首版可使用一个简单生涯资金账本接收分红，并按明确规则转入活动星球；不要把它扩展成复杂金融系统。若采用直接入账，也必须保留完整来源与唯一结算标识。
- 星球移交与新局创建应作为可恢复的整体操作；失败时返回移交前状态，不留下两个活动星球或遗失原世界。

**新星球履约口径**

旧星分红、总督注资、借款、公司救助可以实质帮助新星球发展，但属于融资/外来投资。它们不计入新星球本地经常经营利润和连续盈利达标。

新星球仍按自己的生产、服务、供给和可持续经营能力获得总督资格。继承收益允许玩家更快扩建、尝试更大项目和承受更长建设期；不要通过随资产自动涨价或额外惩罚把成长回报抵消。

交接 UI 至少显示：老星主要收入支出、当地留存、玩家分成、预计分红、已知变化趋势。新星财政页清楚分列本地经营与外来资金。

## 8. 时间、难度与节奏

当前 UI 收敛为暂停、正常、快进三种状态。快进倍率由体验测试选定；现有 1×/4×/12×只作为历史入口，不要求保留全部前台按钮。相同游戏时长、相同行为与随机状态下，速度不改变模拟规则。

日、月、年需使用同一日历定义；可以沿用工程既有年度并明确月长。科研说明、贷款账期、公司审查、事件、分红与人口增长全部使用这套日历，不能各自换算。

简单、标准、困难共用核心规则：

- 简单：更多初始缓冲、更早预警、更长整改窗口、更低事件压力；完整经历核心因果与至少一个可恢复问题。
- 标准：作为首先校准的基准。
- 困难：更紧的预算、储备、期限和合同压力，仍使用相同经营因果。频繁弹窗不等于难度。

信息详细程度是独立的显示选项；简单模式也能展开所有重要因果。不得只在困难模式偷偷启用另一套物流或人口规则。

通关给公司评估报告，展示经营成果、曾经的薄弱项与应对过程。允许以相同种子尝试其他难度，认知与解说可以保留。明确区分三个操作：

- 前往下一颗星球：保留生涯代管资产、合法余额与全局日期，按新合同开始下一次经营。
- 重开当前尝试：默认恢复该星球登陆时的完整生涯检查点，包括全局时间、资金、代管结算账期、随机状态和本地状态；不能只重置地图、补发开局物资，却保留失败尝试期间新增的收益。改变难度时从同一检查点重新应用该开局配置，不叠加两份资助。
- 新建生涯：创建独立的新生涯记录，说明不继承旧生涯资产；旧存档继续保留。

不强迫玩家离开简单模式，不把基础内容全部锁到高难度。难度推进是玩家自愿挑战。

## 9. UI、性能与美术

优先让界面回答经营问题：

- 财政：当地经常净收支、外来资金、承诺支出、近期偿付与现金可支持多久。
- 科研：投入分配与预计完成时间。
- 公司：为什么不信任、什么时候升级、如何整改、援助会付出什么。
- 事件：当前节点、选择代价、截止时间、调查进度和后续影响。
- 地区：缺什么、原因、可用的解决途径。
- 生涯：活动星球、代管星球、预计分红和实际到账。

性能测量区分首次反馈与完成显示，分别测冷、热缓存。重点覆盖殖民地预览、财政总览、地区反复进出、换星球和读档。

普通按钮约 100 ms 内有可见反馈作为待验证目标；已经加载的地区重复进入不得整片重建；仍耗时的工作需要进度/忙碌状态和适当取消能力。记录实际耗时、样本数量与硬件，不能仅报平均 FPS。把大计算移到延迟回调不等于解决主线程卡顿。

保持现有统一美术方向：3D/2.5D 表现场景，2D 面板完成决策。先解决比例、轮廓、地形衔接、状态识别、字体与布局。精修建筑、增加大量肖像、复杂动画和声音不抢占核心机制的工期。

本轮增加的公司、事件、生涯 UI 复用现有样式；按钮与文字真实绘制，不能用一张概念图代替功能。实际检查 1280×720、1920×1080、2560×1440 及已有 UI 缩放档。

## 12. 验证方式与交付要求

以下为现有入口命令，实施前核对脚本与输出副作用。它们不是本次指令编写已经执行过的测试。先在隔离副本运行，或先修正测试输出路径。

在 PowerShell、工作目录 D:\勇敢新世界：

    $colonyEngine = 'D:\勇敢新世界\tools\godot-4.5.1\Godot_v4.5.1-stable_win64_console.exe'
    & $colonyEngine --headless --path 'D:\勇敢新世界\game' --editor --import --quit
    & $colonyEngine --headless --path 'D:\勇敢新世界\game' --script res://tests/sim_tests.gd
    & $colonyEngine --headless --path 'D:\勇敢新世界\game' --script res://world/self_test.gd
    & $colonyEngine --headless --path 'D:\勇敢新世界\game' --script res://tests/ui_contract.gd

存档类型回归入口为 tools/review_save_nested_regressions.gd，可用 --script 传入其绝对路径；同样需要独立用户数据目录。既有模拟通过标识为 SIM_TEST_RESULT 且 failures=0，世界通过标识为 WORLD_SELF_TEST: PASS []。历史诊断探针有的即使发现错误仍以退出码 0 结束，必须检查结果内容，不能只看进程退出码。

运行构建前确认上一版 EXE/PCK 已保留；tools/build.ps1 当前会写 build 目录。构建后必须实际启动新导出的程序，检查源工程以外的资源、字体、配置和存读路径。

新测试的文件名和命令写入实施计划及复现说明。不要只统计旧测试通过数量；需要覆盖本文件的新规则和原审查失败案例。

至少交付：

1. 更新后的源工程与可直接启动的 Windows EXE/PCK 或整包。
2. 一份改动与需求对应表，包含 F01—F12、新科研、公司介入、事件、B 生涯、UI 与性能状态。
3. 数值说明：哪些是固定设计约束、哪些是候选参数、如何计算与比较、哪些尚未充分调平。
4. 实际测试日志、运行命令、退出码、关键构建/配置/存档身份，以及固定种子和复现动作。
5. 可加载的验收场景：危机整改、至少一个事件中段、总督移交前、第二星球收到分红后；注明来自自动流程还是实际窗口操作。
6. 新版实机截图与交互耗时对照，覆盖财政、科研、公司、事件、代管和地区返回。
7. 更新后的 README、验证报告和已知问题；说明旧档兼容、迁移与回退办法。

证据必须区分：静态审查、自动逻辑、源工程运行、导出程序运行、人工实际游玩、截图观察。自动快进不等于真实玩家通关时间；修改一个人口数字不等于验证千万级模拟；静止场景帧率不等于按钮响应。

未完成或未运行的检查明确标记 PARTIAL / NOT_RUN / FAIL，并说明影响。已经通过的有意义检查无需无理由反复执行；发生新修改、失败或未解问题时再针对性重验。

执行过程中优先保住经营闭环、公司介入、事件真实后果和 B 跨局连续性。需要控制规模时，减少不必要的建筑、技术与美术扩展，保持上述已确定机制的完整性。

一、用户已经确认的游戏方向

1. 单机、全免费、Windows 原生桌面程序，支持离线游玩，不采用网页或浏览器壳作为游戏交付形式。没有付费货币、付费科研槽、付费加速、广告及强制联网。
2. 玩家是殖民公司的外包专员。公司给少量人口、物资和采矿设备，玩家签署殖民经营对赌协议。殖民地需要自负盈亏；履约后取得总督资格，继续向公司缴纳约定税款；经营失败则结束本局。
3. 前期玩家统一经营核心产业；随着殖民地成长，允许移民及当地企业经营部分产业，形成混合经济，减少后期逐个设施操作的负担。
4. 开局可以选择不同优势，包括额外资金、面向工人的招募合作、面向研究人员的招募合作。各路线都必须有独立可行的起步方法。
5. 开局可以开采多种低门槛资源。“轻型矿”指初始装备能够开发、部署成本较低的矿床，不是只允许开采一种元素，也不是按元素轻重划分解锁顺序。
6. 发展从矿产出口起步，逐渐建立农业、加工与制造，再发展教育、科研、商业等服务业。基础产业在后期仍有用途。
7. 星球有真实影响经营的地理差异。地形、气候、水源、资源、距离和运输能力必须改变选址与投资决策。
8. 人口通过移民和自然增长增加，按地区、年龄段、教育与职业群体统计。不要建立每个居民的个人日程、性格、关系与寻路模拟。最终设计需要能够表达千万到亿级人口。
9. 有能够预警和应对的小型危机与事件。挑战来自现金流、资源调度、空间布局及发展取舍。
10. 美术、UI、人物肖像、星球外观是首版验收的一部分。参考 TerraGenesis 的行星表现，以及 Stellaris 的科幻经营信息组织，形成统一、原创的视觉语言。

二、本 Demo 采用的具体范围

以下是为了做出可玩的首版而设定的实施默认值，可以在不改变上述方向的前提下调整并记录原因：

- 暂名《殖民契约》，只作项目识别，不代表最终名称。
- 目标体验长度约 20—40 分钟，允许暂停和加速。实际时长需要试玩后报告，不能仅凭设计估计宣称达标。
- 先做一类宜居大陆星球，可呼吸大气与基础生态条件作为既定设定。海洋、热带、高山及荒芜星球的完整独立玩法留待后续。
- 一个可旋转的 3D 行星总览，配合一个可进入的地区建设视图。地区采用 2.5D 或轻量 3D 地形，建筑有可辨识外形。允许切换场景，不要求从太空无缝落到街道。
- 一颗星球起步只有一个殖民据点，Demo 中必须能建立第二个据点并通过运输形成有用分工。首版每局最多开发两个地区，每个地区一个据点；玩家仍从多个候选区域选择登陆点和扩展点。其余区域用于地理展示、勘察和选址比较，不扩展第三据点及全行星建设。
- 包含三种开局优势、至少三种开局可开发的矿产、一条农业供应链、一条加工供应链、一个小型教学科研机构，以及一个实际运转的民营企业类型。
- 小规模科研树，约 6—8 项技术；3—5 个确实改变局势的事件即可。
- 有合同达标、失败和达标后继续沙盒经营三种状态。
- 不做星际舰船驾驶、银河战争、外交、多人物生活模拟、全星球真实流体与大气模拟。相关位置不能用大量无作用按钮占据 UI。

三、核心游玩过程与合同

玩家应能完成：选择起步优势和星球种子 → 查看合同 → 勘察并选择登陆点 → 建立生活与采矿设施 → 出售资源支付支出 → 建设农业或加工能力 → 扩展第二据点与运输 → 引入一家民营企业 → 达成阶段合同，取得总督资格并进入后续经营。

合同必须在开局清楚显示资金与物资支持、考核时间、经营目标、后续税制及失败条件。实现少量可验证的阶段目标，例如连续若干结算期经营结余非负、拥有最低必需品储备、形成两个有效连接的据点，以及满足基本住房和就业条件。

具体数值写入配置数据，经过试玩调平。合同中的经营结余以公共殖民管理账户为口径，区分经常性经营收支、建设投资和融资；贷款、一次性注资及变卖资产不能算作持续经营收入。居民与企业账户另外列示，不能拿星球总产值代替公共账户的支付能力。不要让合同目标要求一个尚未解锁、尚未实现或在当前种子下不可到达的系统。公司征收的税需要明确税基、税率、起征时点与结算方式，默认在总督阶段按公共账户正的经营结余计算公司分成，民营企业向本地缴税另行结算；避免亏损时仍从不存在的利润征税。

资金不足前要能看见未来支出和预计可维持时间。失败应由清楚、持续的经营条件触发，例如到期关键付款无法履行且宽限期结束，或居民必需供应长期崩溃。设置明确、有限的宽限期，不能无限救济，也不能一次支出使现金短暂到零就无提示立刻结束。

四、经济、产业与混合经营的最低闭环

经济至少记录公共经营账户、居民群体资金、民营企业资金，以及对外交易。可以使用简化的汇总模型，不要求复杂价格博弈或全经济主体仿真。

矿物和制品出口、外部订单、外来投资等对外资金流要可追踪；工资、居民消费与本地税款属于内部转移，要有付款方与收款方，不得在多本账里重复增加总资金。明确初始资金、外来移民携带资金和企业投资的来源。无需额外实现外汇兑换系统。

物资按据点实际储存并沿运输网络移动。地图上遥远矿区的产出不能无运输地立刻进入首府仓库。建设需要实际资金和物资；生产受岗位、电力、水、输入物资和可用产能约束，短缺原因能够在 UI 中解释。

资源总类控制在 6—8 种左右，例如三类初始矿产、食品、建筑材料、机械部件；资金单独记账，水电可作为供需能力而非又一组商品库存。先完成少量有意义的配方，不扩展几十种材料。

矿床至少有已探明储量、可开采条件、产量或品位差异、开发成本及到据点的物流条件。矿产在正常模式下有限储量；发现或更新储量有明确规则。高售价矿床可以因运输、建设及运营成本较高而不适合开局。

农业应减少食品进口；加工应能够提升某些出口价值或减少常用材料进口。进口和出口受到港口或运输吞吐约束，有费用及结算规则。自动贸易政策至少支持保留最低库存后出售余量，避免玩家反复手动卖货。

研究人员路线必须保有最低生产与生计条件；研究人员通过勘探、加工改进或技术降本产生早期实际价值。小型教学科研机构消耗工资、经费或材料，产生研究进度和少量职业培训。科研支持选择项目与投入优先级，无付费跳过。

混合经济在 Demo 中必须真实发生：达到条件后，有企业使用明确的投资资金，自主建设或租用一个允许的经营点，雇用人口，支付经营成本，获得销售收入，缴税，并自动维持经营。可以只实现本地食品加工或商业服务中的一种；不要同时做完整市场经济。

玩家能够设置允许经营的行业或地区、税率及基本供应政策。民营企业正常运营不需要逐日点击；经营失败时给出可理解的原因。出现民营企业后，公共设施和玩家保留的关键产业仍可直接管理。

五、星球生成、地图与地理决策

采用可重复的 seed 和明确的生成器版本。相同版本、相同种子及设置生成相同世界。地图生成顺序为：

1. 整体条件：尺寸、水陆比例、冷热基准、起伏与资源条件。
2. 连续的大陆、海洋、山脉、高原、盆地及平原。
3. 简化温度、降水、水系与流域。
4. 生物群落、土地用途潜力及矿产。
5. 开局可玩性校验。

温度可以通过纬度与海拔等近似规则生成；降水考虑海陆、主风向与山地；河流、湖泊和湿地要与地势基本一致。规则以可解释和支持玩法为目标，不以科学预测精度为验收标准。

Demo 可提供小、中、大三个尺寸档，但必须让尺寸影响实际面积/路程或开发规模。气候由多个参数联合决定，环境承载由可利用土地、水、气候与基础设施共同约束，不做一个只随尺寸变化的固定人口上限。

全球视图和地区视图必须读取同一个权威世界状态。河流、海岸、矿藏、殖民点和运输连接在两个视图中对应；局部细节可以细化，但不能换成与全球地理无关的另一张随机地图。显示尺度与模拟尺度可以分离。

普通开局应存在能够存活的区域，不能保证所有资源都集中在登陆点。提供一个经过验证的推荐种子，同时保留自由输入种子。至少展示：肥沃河谷与矿区分离、绕山和跨山运输成本不同、第二据点能改善一种真实供应问题。

可采用自动寻路生成的道路或运输连接，不要求第一版逐段手工铺路。路径需要考虑地形和允许的运输方式。陆运不能直接穿海；没有海运设施时，断开的陆地应清楚显示不可达。

六、人口与事件

以据点/地区为单位汇总人口、未成年人与劳动人口、教育/职业、就业、住房及必需品满足程度。人口流动、出生和成长进入模拟；成长速度按游戏时间推进，暂停时停止。Demo 的主要增长来自移民，出生机制可通过较长时间测试验证，不强求短局内增长到巨大规模。

总人口、就业和职业分组必须一致，不能出现负人口、同一工人重复占多个全职岗位。UI 应能说明为什么有空岗位却招不到合适人才。

事件优先与当前状态相连，例如运输中断、矿物报价变化、人才迁入、季节性供水压力。至少一个事件有提前预警、两种不同成本的应对方式，以及可追踪后果。事件不能仅有故事文字和无实际影响的按钮。

总体定位：克制、清晰、带工业质感的写实科幻。行星与地表是主要视觉吸引力；UI 有信息层次，人物肖像用于建立殖民经营的叙事感。

建议统一色板：深空背景 #09121C，面板 #132333，主文字 #E7EEF2，次级文字 #A6BAC8，交互强调 #62C7C5，资金/合同强调 #D8B16A，危险 #E46F68。颜色可按实机对比度调整，但全项目统一。危险不能只靠颜色表达，还要有图标或文字。

使用有完整中文字形的可分发字体，优先检查本地可用的思源黑体/Noto Sans CJK 等字体及其许可。正文、数字、标题有清楚层级，1920×1080 下正文以约 16—18 像素为设计起点，提供 UI 缩放，避免密集小字。

行星：真正的可旋转 3D 球体，具有可辨识大陆、海岸、海洋、山脉/地势、植被区与极区，适度的云层和大气边缘，合理的光照。地形高度可克制夸张以帮助阅读。夜侧城市灯光随实际聚落出现。提供清晰的经营观察模式，夜色和云层不能持续遮住可操作对象。接缝、极点及近景不能出现明显破洞或异常拉伸。

地区：地表高低、水岸、农业地、矿区、道路与建筑有统一比例、光照和材质。首版可以采用少量精制模块化建筑，必须有可读的轮廓和建设/运行/停工状态。资产种类少可以接受，最终交付不能满屏默认立方体、调试网格和文字标签替代场景。

人物：先做 3 张同风格半身肖像，分别服务于公司联络人、工程负责人、科研负责人。统一写实程度、镜头、背景处理与照明，人物具有可辨识职业服装和外貌。肖像用于合同、事件和科研界面，无需制作可行走角色与骨骼动画。

图标：至少覆盖本 Demo 实际存在的资源、主要建筑类别和警报状态；统一尺寸、线条/填充风格和选中状态。禁止用 emoji 充当正式资源图标。

有图像生成能力时，可使用对应图像工具制作肖像及适合位图的素材；有 3D 建模工具时，可用其制作模块化资产。文字、按钮、图表、数值和交互区域必须由游戏 UI 实际绘制，不可烘焙进一张界面图片冒充交互。缺少某个资产工具时，采用一致的可实现方案并如实记录，不得把未接入引擎的图片算作完成。

先完成一个代表性实机画面：行星/地区场景、常驻 UI、一个详情面板和一个肖像弹窗按统一规范运行。自查并修正比例、字体、材质和色彩后，再扩展其他页面和资产。视觉基准在第一轮定清，后续根据实际截图进行必要修整。

八、UI 与操作

主界面以地图为中心。顶部显示资金、近期收支、人口、关键供应和日期/速度；左侧放少量功能入口；右侧显示当前选中地区、据点、设施或运输路线的详情；底部提供可收起的任务/预警区。默认面板不要遮住地图大部分区域，避免所有窗口同时常驻。

必需流程与页面：主菜单及继续游戏、新建游戏/起步优势/种子、合同与登陆选址、行星总览、地区建设、经济明细、科研、事件、保存读取、成功及失败。

经济面板能追溯收入、工资、进口、维护、税款与运输费用，并显示库存、净变化和缺口原因。建设预览显示价格、物资需求、工期、运营成本、选址限制与资源条件。

所有主要按钮要有真实效果；未满足条件时明确说明原因。支持工具提示、选中反馈、返回/取消、危险操作确认、地图缩放旋转/平移，以及空格暂停。界面打开时避免鼠标穿透到地图误建。

采用中文界面。至少实际检查 1280×720、1920×1080 与 2560×1440 的布局和 UI 缩放；文字、按钮、滚动区域、弹窗与工具提示不能被裁切或互相覆盖。允许较低分辨率折叠次要信息。

九、技术与文件组织

若目录已有项目，先读取现有约束并尽量复用。若为空，默认使用经核实的稳定版 Godot 4.x 与 GDScript；记录引擎和导出模板的准确版本并保持匹配。选择适合本机和目标硬件的渲染器。确有工程理由可以调整技术选择，但要保持 Windows 原生可执行交付和视觉要求。

技术参考：Godot 官方 Windows 导出文档 https://docs.godotengine.org/en/stable/tutorials/export/exporting_for_windows.html ，渲染器说明 https://docs.godotengine.org/en/stable/tutorials/rendering/renderers.html 。实施时按实际安装版本核对。

建议按 world、simulation、economy、population、research、events、ui、assets、data、tests、docs 等职责组织，不要把生成器、账本和所有 UI 写进一个大脚本。具体文件和接口由实现 Agent 在简短实施计划中确定。

模拟采用与渲染帧率分离的固定步进。暂停和不同加速档不能改变相同游戏时间下的经济规则。随机生成和事件使用受控随机源，存档保存必要随机状态。

保存世界种子、生成器版本、地图或其可恢复状态、人口、账本、库存、设施、运输、科研、合同、事件、企业与模拟时间。保存采用版本号和安全写入；读档后能继续相同局势，不能仅保存一个种子重开新局。不要把全部经济历史无限累积导致后期内存失控。

数值、配方、合同、开局配置、技术与事件尽量数据驱动。保留一份可靠的推荐种子和可复现的验收存档。正常模式和开发调试功能应明显分开。

十一、验证与验收

必须区分脚本静态检查、自动化逻辑测试、编辑器运行、导出程序运行、实际游玩与截图观察。不能用其中一种替代其他证据。

逻辑验证至少覆盖：
- 同种子同版本生成一致；若干预先固定种子通过开局可玩性检查。
- 资金内部转移和对外流量可以核对，物资生产、消耗、运输和库存没有无来源增长或重复扣减。
- 无资源、断路、无岗位、供水供电不足时，建设与生产按规则受限。
- 第二据点的货物需要运输时间与运力；路径无法陆路穿海。
- 暂停不推进模拟；相同模拟时长下不同速度档的结果一致，按明确的数值误差规则比较。
- 人口、岗位与职业分组守恒；民营企业确实支付成本、经营并缴税。
- 保存读取后关键状态一致；继续运行不丢失订单、路线、合同或随机事件状态。
- 合同成功、失败、宽限期和成功后税款的边界条件正确。

实际操作验收至少覆盖：
- 从新游戏建立据点、生产并完成第一笔出口。
- 建立第二据点并看到真实跨区运输解决供应问题。
- 开局三种优势各有一条可以验证的生存路径，不能只有一个选项能过关。
- 民营企业落地并自动运营，玩家能看到与公共经营不同的收支和控制方式。
- 完成一次合同成功路径和一次失败路径；验证保存、退出、启动导出程序和读档继续。
- 实际检查三个目标分辨率，截取最终行星总览、地区经营、经济/合同、科研/人物事件等画面，检查文字、对比度、遮挡和资产风格。

性能在本机测量并记录硬件、分辨率、代表性场景与测试方式，不凭估计写“流畅”。增加人口统计规模时，不应按居民人数线性创建场景节点。大型人口压力测试与真实百万居民完整经济模拟要分开标注。

推荐种子能运行不等于所有随机种子都已验证；自动脚本通关不等于玩家实际试玩；生成了截图文件不等于看过截图。报告中保留 FAIL、PARTIAL、NOT_RUN 及具体限制。
